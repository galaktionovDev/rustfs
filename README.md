# 📦 RustFS — Роль для развертывания объектного хранилища

## 🔍 Описание

Роль обеспечивает автоматизированную установку, конфигурацию и масштабирование высокопроизводительного S3-совместимого объектного хранилища RustFS на Linux-серверах (поддерживаются Debian, Ubuntu, RED OS, Astra Linux).

Поддерживаемые сценарии:
- Single Instance — автономный single-node сервер RustFS.
- High Availability (HA) — отказоустойчивый кластер (от 2 до 4+ узлов).
- Высокодоступный балансировщик нагрузки на базе HAProxy + Keepalived (с плавающим VIP).
- Автоматическая подготовка XFS-дисков и каталогов данных.
- Установка RustFS Server и CLI-клиента (rc).
- Настройка и автоматическая генерация системных служб systemd.
- Управление бакетами (создание, удаление, проверка прав).

## 🚀 Возможности роли

### Single Instance

- Развёртывание изолированного экземпляра RustFS.
- Использование одного или нескольких локальных XFS-дисков.
- Автоматический экспорт точек подключения connection_url и console_url.

### High Availability (HA) & Scale-Out

- Развёртывание распределенного RustFS-кластера на группе узлов.
- Автоматический сбор топологии дисков и узлов на основе инвентаря Ansible (rustfs_drives_map).
- Scale-Out без потери данных: автоопределение существующих и новых нод с последующей безопасной переконфигурацией всей топологии кластера.

### Высокодоступный балансировщик (HAProxy + Keepalived)

- Развёртывание парных LB-узлов с отказоустойчивым виртуальным IP (VIP).
- Балансировка L4/L7 для API (rustfs_api_port) и веб-консоли (rustfs_console_port).
- Автоматическое отслеживание доступности HAProxy скриптом check_haproxy.sh.

## 🔧Ключевые переменные

Ниже приведены основные переменные. Полный список находится в roles/*/defaults/main.yml.

### Базовые настройки сервера

| Переменная               | Назначение                             | Пример              |
|--------------------------|----------------------------------------|---------------------|
| `rustfs_install_server`  | Установка RustFS Server                | `true`              |
| `rustfs_install_client`  | Установка CLI-клиента (rc)             | `true`              |
| `rustfs_root_user`       | Администратор RustFS (Access Key)      | `rustfs_admin`      |
| `rustfs_root_password`   | Пароль администратора (Secret Key)     | `SuperSecret123`    |
| `rustfs_server_port`     | Порт API S3                            | `9000`              |
| `rustfs_console_port`    | Порт веб-консоли                       | `9001`              |
| `rustfs_alias`           | Имя профиля/алиаса для rc              | `myrustfs`          |


###  Диски и данные

Рекомендуется использование файловой системы XFS с опцией монтирования noatime.

| Переменная               | Назначение                                                                               |
|--------------------------|------------------------------------------------------------------------------------------|
| `rustfs_server_datadirs` | Список явных путей точек монтирования данных.                                            |
| `rustfs_extra_disks`     | Массив описания дисков для автоматической разбивки, форматирования и монтирования.       |

###  Режим работы и кластеризация

| Переменная                   | Назначение                             | Допустимые значения                     |
|------------------------------|----------------------------------------|-----------------------------------------|
| `rustfs_cluster_mode`        | Режим развертывания.                   | "Single Instance" | "High Availability" |
| `rustfs_cluster_nodes_group` | Имя инвентарной группы узлов хранилища | `node`                                  |

###  Настройки Балансировщика (HAProxy + Keepalived)

| Переменная             | Назначение                      | Пример              |
|------------------------|---------------------------------|---------------------|
| `rustfs_enable_lb`     | Активировать развертывание LB   | `true / false`      |
| `rustfs_lb_group`      | Имя инвентарной группы LB-узлов | `lb`                |
| `keepalived_vip`       | Виртуальный плавающий IP-адрес  | `192.168.1.100`     |
| `keepalived_router_id` | Уникальный ID VRRP-группы       | `51`                |

###  🧾 Действия с бакетами

Управление бакетами выполняется через клиент rc:

- `create_bucket.yml` — идемпотентное создание S3-бакетов.
- `delete_bucket.yml` — удаление бакетов.

Авторизация выполняется через безопасное использование сгенерированного профиля/алиаса (rustfs_alias), без явной передачи паролей в аргументах командной строки.


###  ✅ Проверки после развертывания

1. Сервисы RustFS на узлах хранилища

    `systemctl is-active rustfs-server`

    `systemctl is-enabled rustfs-server`

 2. Диски и точки монтирования

    `mount | grep /mnt/`

    `ls -ld /mnt/*`

    - Ожидаемый результат: ФС xfs, наличие опции noatime, владелец каталогов — пользователь службы RustFS.

4. Health-эндпоинты RustFS

    Проверка прямого ответа ноды или через VIP балансировщика:

    `curl -L -I http://<VIP_ИЛИ_IP_NODE>:9000/minio/health/live`

    `curl -L -I http://<VIP_ИЛИ_IP_NODE>:9000/minio/health/ready`

    - Ожидаемый код ответа: HTTP/1.1 200 OK.

5. Проверка работы CLI-клиента (rc)

    `rc alias ls myrustfs`

    `rc ls myrustfs`

    - Ожидание: Список алиасов корректно выводится, вывод бакетов выполняется без ошибок AccessDenied или проблем с таймаутами сети.

6. Топология и статус кластера (rc admin)

    Для HA-кластера проверяем согласованность всех узлов и дисков:

    `rc admin info myrustfs`

    - Ожидание:

        - Количество серверов совпадает с фактическим числом нод в группе node;

        - Все узлы находятся в статусе Online;

        - Диски примонтированы и не имеют ошибок (errored / offline).

7. Работа с S3 API и проверка бакетов

    Проверка создания, листинга и удаления тестового бакета через CLI-клиент:

    - Создание тестового бакета

    `rc mb myrustfs/test-health-bucket`

    - Проверка наличия бакета в списке

    `rc ls myrustfs`

    - Удаление тестового бакета

    `rc rb myrustfs/test-health-bucket`

    - Ожидание: Все команды выполняются без ошибок AccessDenied, сетевых таймаутов или ошибок разграничения прав.

8. Доступ к веб-консоли RustFS

    1) Перейдите в браузере по адресу:

        `http://<VIP_ИЛИ_IP_LB>:9001 (или http://<IP_NODE>:9001)`
    
    2) Авторизуйтесь с использованием учеток:
        
        Логин: значение `rustfs_root_user`

        Пароль: значение `rustfs_root_password`

    3) Ожидаемый результат:

        Успешный вход в интерфейс управления;
        Корректное отображение существующих бакетов, графиков утилизации дисков и активных сессий.

9. Проверка результативности Scale-Out (при расширении)

    Если выполнялось масштабирование кластера через scale_out.yml:

    1) Проверьте статус службы на новых нодах:

        `systemctl status rustfs-server`

    2) Убедитесь, что новые узлы появились в общей топологии:

        `rc admin info myrustfs`

    3) Проверьте, что новые узлы автоматически добавились в конфигурацию бэкендов HAProxy на балансировщиках:

        `grep "server" /etc/haproxy/haproxy.cfg`

    - Ожидание: В HAProxy добавлены новые серверы, статус всех бэкендов в haproxy-stats — UP.
